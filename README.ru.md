## ✨ Что это

По полю 160×160 в плотной мозаике движутся ~9200 цветных точек. Код существует только как **группа точек**: она собирается в подвижный блок, который ведёт себя как живое желе — тянется, дышит, пульсирует по размеру, а поверх идут глобальная рябь и вихри («жидкая линза»).

Одиночный кадр почти неотличим от фона: плотность точек, время жизни и частота появления в штрихах цифр и в фоне специально выровнены — принцип *zero knowledge per frame*. В веб-версии кадры приходят потоком в реальном времени: готового файла нет, а без наведения поле полностью закрыто.

## ⚙️ Как это работает

| # | Что происходит |
|---|---|
| 1 | Плотное равномерное поле точек: шаг сетки 2 px, точки 1–2 px, палитра из 6 сочетающихся цветов. |
| 2 | Первую секунду код невидим — точки цифр просто движутся вместе с фоном. |
| 3 | Следующие 1.5 с точки слетаются из случайных мест в свои клетки (сборка). |
| 4 | Дальше надпись живёт как «желе»: перенос + вращение ±12° + «дыхание» ±2.5 px + деформация штрихов, разрывы/склейки клеток и пульсация размера ±25%. |
| 5 | Точка, залетевшая в клетку символа, «захватывается» и начинает двигаться вместе с текстом (без скрытия и без скачков рождения/смерти). |
| 6 | Поверх — «жидкая линза» (глобальная рябь и вихри); по фону дрейфуют разрывы и пустые места. |
| 7 | Кадры транслируются потоком (20 fps) и не скачиваются повторно; ответ проверяется по SHA-256 хэшу с солью на сервере, код живёт 30 секунд. |

## 🚀 Быстрый старт

**Веб-приложение** (.NET 10):

```bash
dotnet run --urls http://localhost:5199
```

`appsettings.json` → `CapGen:Path` (бинарь генератора), `CapGen:Digits`, `CapGen:Fps`, `CapGen:Seconds`, `CapGen:Mode` (`classic` или `jelly`).

**Генератор** (Rust):

```bash
cd generator
cargo build --release
./target/release/capgen.exe 4821 out.gif 20 30 jelly   # код, файл, fps, секунды, режим (classic|jelly); .bin — сырые кадры для стрима
```

## 🧪 Как тестировать (моделям и людям)

1. Сделать набор с метками: `./generator/eval.ps1 -N 100`
2. Отдать GIF (или спрайт-листы из `samples/`) модели с таким промптом:

> Проанализируй анимацию. В ней спрятан код из 4 цифр: это единственная группа точек, движущаяся как единое целое. Напиши алгоритм (Python + Pillow/PyAV), который по файлу GIF выдаёт 4 цифры, и измерь точность на предоставленных примерах.

3. Посчитать результат: `./metrics.ps1 -Csv answers.csv`

## 🏆 Публичный вызов

- **Цель:** решатель, читающий 4 цифры из одного GIF — ≥ **50%** точных совпадений на закрытом наборе из 100 GIF.
- **Разрешено:** любые CV/ML-подходы, обучение на своих данных (генератор открыт).
- **Запрещено:** читать ответ из метаданных, использовать метки закрытого набора, человеко-фермы.
- Полные правила: [`CONTEST.md`](CONTEST.md)

## 🧠 Решатели и хроника атак

| Решатель | Точных совпадений | По цифрам |
|---|---|---|
| Эталонная CV-атака (`generator/src/bin/solve.rs`) | **0 / 50** | ~10–13% (случайность) |
| `solve2.rs` — усреднение фона + EM (наш) | 50/66 на v8 · **0/10 на текущей (v10)** | 87.5% → 25% |
| `solve3.rs` — flow-вариант (исправлен) | **0 / 10** на текущей (v10) | 25% |
| `solve2.rs` v2.1 — адаптация под масштаб (WIP) | 0 / 10 | 25% |
| Сообщество (Z.ai, Dmitrii) — CV-попытки (защита v8) | **4 / 100** | ~52% |

📖 Полный разбор: [`docs/ATTACK-HISTORY.md`](docs/ATTACK-HISTORY.md) — как создавались решатели, какие выводы делались, как ужесточалась капча и почему текущая версия не поддаётся.

## 📁 Структура репозитория

```
generator/         Rust: capgen (GIF/raw, режимы classic/jelly) + solve.rs, solve2.rs, solve3.rs (решатели)
Pages/, wwwroot/   веб-приложение ASP.NET Core Razor Pages (тёмный UI, 6 языков)
samples/           10 GIF с метками + спрайт-листы (labels.csv — только для подсчёта)
docs/              скриншот + хроника атак (ATTACK-HISTORY.md)
eval.ps1           генерация N GIF и замер эталонного решателя
sprite.ps1         GIF -> спрайт-лист PNG (с диапазоном кадров)
metrics.ps1        точность + таблица «успех за N попыток»
CONTEST.md         правила публичного вызова
NOTICE.md          авторство, дата, SHA-256 отпечатки исходников
```
